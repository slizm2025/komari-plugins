# Komari 月度流量配额监控插件 (`traffic-quota`)

专为 **Komari >= 1.5.0（已针对 Komari 1.6.1 实测适配）** 开发的单机月度流量消耗与剩余流量监控插件。

## 为什么单独做这个插件？

- Komari 1.6.1 的 `metrics.db` 默认仅保留 **1 天** 原始指标数据，仅查指标库无法还原完整 30 天账单周期；
- VPS 商家的**每月流量重置日**往往与「机器到期日」不同，且计费口径各异（双向总和 / 仅出站 / 仅入站 / 取单向较大值、1024 GiB 或 1000 GB）；
- 本插件在 Komari 持久目录 `__storageDir__` 中维护独立的每日增量账本（保留 100 天，体积仅十几 KB），彻底解决「指标库过期」和「VPS 重启导致网卡计数器清零」两个痛点。

## 核心能力

1. **每台 VPS 独立配额规则**
   - 独立设置 **启用开关**、**每月开始/重置日（1–31，小月自动对齐月末）**、**月度流量上限（支持 GB / TB）**、**计费方式（双向 / 仅出站 / 仅入站 / 取单向较大值）**、**可选备注**。
   - **本期初始已用校准（GB）**：安装插件时如果本周期已在商家侧用掉一部分流量，直接填入校准值即可立刻对齐总已用与剩余流量；**到达下一个账单重置日时该校准值会自动归零**，不会污染下月统计。
2. **防重启清零 + 零额外探针**
   - 每 5 分钟通过 Komari 原生 `common:getNodesLatestStatus` 采样网卡累计字节数，自动识别计数器回退（VPS 重启）并无缝累加，首次运行自动回溯最近 24 小时历史记录。
   - 无需在被监控 VPS 上安装任何额外脚本或进程。
3. **首页卡片进度条注入 + 独立看板页**
   - 自动识别 Komari 1.6.1 默认主题（`.km-node-card[id]`）及主流第三方主题，**仅对已启用配额的节点**在卡片中插入「月度流量进度条 + 本期已用 / 剩余流量 + 距重置天数」。
   - 与 `latency-monitor`（延迟与丢包插件）天然兼容：检测到 `.klm-panel` 时自动排版在其上方，互不遮挡。
   - 独立页面「**月度流量配额**」提供全节点 KPI、每日柱状图、预计本期总消耗与管理员可视化配置弹窗。

## 安装与配置步骤

1. 在 Komari 后台 → **插件（Plugins）** → 上传 `dist/komari-plugin-traffic-quota-v1.0.0.zip` 并授权启用。
   - 若此前装了 `net-forecast` 且不再需要，建议顺手在插件列表关闭 `net-forecast`，避免页面右下角多出多余浮层。
2. 在插件设置中确认全局项（默认北京时间 `UTC+8`、`1024 GiB` 进制、80% 预警 / 95% 告警）。
3. 打开导航栏中的「**月度流量配额**」页面 → 点击右上角「**配置各节点配额**」：
   - 逐台勾选启用，填写各 VPS 的**每月开始日**、**月度流量上限**、**计费方式**及（可选）**本期已用校准值** → 保存即刻生效。

## 本地测试与重新打包

```bash
cd komari-traffic-quota
./build.sh
```
